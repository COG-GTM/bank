1. Goals

This document is a knowledge base of the bank service portfolio as implemented at commit 7998b9b, and a proposal for a domain-driven re-architecture delivered incrementally (strangler pattern). It is not a platform, runtime or language upgrade: the stack (Java 21, Spring Boot 3.3.4, Axon, MySQL) is kept, and this run changed no application code, build file or schema.

  • Record, with a file:line citation, who owns each table, which services call which, and which business rules are actually enforced.
  • Cross-check the repository's own README claims against the code (code wins).
  • Propose bounded contexts with one owner per table, one anti-corruption layer (ACL) per external system, and a roadmap of slices each with a measurable "done when".

Detail beyond this document lives in the inventory produced alongside it (~/inventory/bank.md, 130+ cited facts). No build, test or run script was executed.

2. System as-is observed

Six Maven modules (pom.xml:19-26), each a Spring Boot deployable. Four have a MySQL schema of their own; the account service additionally uses Axon Server as its event store. The Angular UI is a separate repository (README.md:154). All inter-service calls are synchronous OpenFeign over Eureka names; none go through the gateway.

6. Re-architecture proposed

The ownership table yields five business contexts plus an edge. Each table gets exactly one owner; each external system sits behind exactly one ACL; reporting is a read model fed by events; contexts exchange past-tense events, never copied DTOs.

Design rules

  • One owning context per table; other contexts hold only event-derived snapshots (fixes F3, F10).
  • One ACL per external system (SMTP → Notification ACL; Axon Server stays internal to Ledger); the ACL owns the contract, callers bind to it via a contract test (fixes F1, F2).
  • Money(amount, currency) and an injected Clock are domain types; events carry the currency and the ledger timestamp (fixes F4, F5).
  • State transitions are explicit commands (OpenAccount → ActivateAccount); TransferFunds is a saga with a transfer id and TransferFailed event (fixes F6, F7).
  • JWT verified once at the edge with a single secret source; role policy per route; validation enforced at every context boundary (fixes F8, F9).
  • Deployment manifests derive from the module list; schemas managed by migrations, ddl-auto=validate (fixes F11).

7. Roadmap proposed

Six strangler slices; none completed at this run. The ACL goes first (highest risk, least business logic), then the context with the fewest dependants (Customer: one dependant), then the edge, then the ledger, the read model, and deployment alignment.
